# OciDeck — Open-Source Licence Compliance

OciDeck is released under the **EUPL-1.2** (see [`../LICENSE.md`](../LICENSE.md)).
This document records the policy that the project only includes open-source
software, how that is verified, and the result of the latest check.

## Policy

Every dependency and every bundled asset must be available under an OSI-approved
open-source licence. No proprietary or source-unavailable components are shipped.

Accepted licence families: **MIT, BSD (2-/3-Clause), Apache-2.0, MPL-2.0, ISC,
Zlib, BSL-1.0, Unlicense, SIL OFL-1.1, CC0** (and EUPL-1.2 for OciDeck itself).
Anything else — in particular GPL/AGPL/LGPL or a missing/unknown licence — is
flagged for review before it can be added.

## How to verify (repeatable)

A script scans the resolved package graph (direct **and** transitive) and
classifies each licence:

```sh
make licenses          # or: dart run tool/check_licenses.dart
```

It exits non-zero if any package has an unrecognised or non-open-source licence,
so it also runs as part of `make check-full` and can be wired into CI.

> The script reads each package's `LICENSE` file from `.dart_tool/package_config.json`,
> so run `flutter pub get` first. Re-run it whenever dependencies change.

Bundled (non-package) runtime assets — the JavaScript inlined into the HTML
export and the bundled fonts — are tracked by hand in
[`../THIRD_PARTY_NOTICES.md`](../THIRD_PARTY_NOTICES.md).

The authoritative, version-pinned, machine-readable inventory of **every**
component (packages, vendored bundles, forks, fonts, SDKs) — each with its
classified licence — is the Software Bill of Materials, generated by `make sbom`
and documented in [`SBOM.md`](SBOM.md). It reuses the exact same licence
classifier as `make licenses` (`tool/license_detect.dart`), so the two can never
disagree.

### OWASP WSTG — attribution and share-alike

**What is bundled:** the WSTG **checklist index** — for each of the 97 tests its
stable id (`WSTG-INFO-01`), its canonical English title ("Conduct Search Engine
Discovery Reconnaissance for Information Leakage") and its category. It fills a
`checklist` slide with the standard's test list in one click. The guide's actual
substance — how to test, what to look for, the remediation guidance — is **not**
bundled; every entry points back to owasp.org for that.

**Attribution.** The Web Security Testing Guide is © the OWASP Foundation and its
contributors, published under
[CC-BY-SA-4.0](https://creativecommons.org/licenses/by-sa/4.0/). OciDeck
reproduces the v4.2 checklist index unmodified in substance, reformatted as Dart
data. Source: <https://owasp.org/www-project-web-security-testing-guide/>.

**Share-alike.** The CC-BY-SA-4.0 terms travel with that dataset: anyone
redistributing it — as part of OciDeck or lifted out of it — does so under
CC-BY-SA-4.0 with this attribution. Share-alike attaches to **the WSTG material**,
not to OciDeck: the app bundles it as a *Collection* (the licence's own term for
including a work alongside other, separate works), so the EUPL-1.2 code around it
is unaffected. Reformatting into Dart structures is the one point where a reader
could argue *Adapted Material* rather than mere reproduction; either way the
obligation is the same one already discharged here — attribute, name the licence,
and keep the dataset under it.

> **This paragraph used to say the opposite.** It claimed test standards were
> referenced "by name only" and that no WSTG checklist content was bundled, so
> share-alike was not triggered — while `wstg_catalog.dart` had carried the
> 97 verbatim titles all along. The paragraph even named the condition for its own
> undoing ("should verbatim checklist content be bundled later…"); nobody came
> back to it when the module landed. Recorded here so the next reader knows this
> section was checked against the code, not assumed.

**Referenced by name only** (no content bundled, so nothing to license): PTES,
OWASP MASTG, OWASP ISTG and OWASP FSTM, used for the scope-to-standard mapping
(Infra→PTES, IoT→ISTG, Firmware→FSTM, Mobile→MASTG). Nominative use of a
standard's name carries no licensing obligation. Should any of their content be
bundled later — the same way WSTG's was — it belongs in the table above **in the
same commit**.

## A note on Apache-2.0 and the EUPL

A few components are Apache-2.0 (e.g. MathJax in the HTML export, and some Dart
packages). Using Apache-2.0 libraries as unmodified dependencies in an EUPL-1.2
work is fine. Note, however, that Apache-2.0 is **not** on the EUPL's list of
"compatible licences" (which governs the *outbound* relicensing of derivative
works under Article 5 EUPL). This only matters if you create a combined
derivative work that must be relicensed; it does not affect bundling these
libraries as-is. If you need formal certainty for a specific distribution
scenario, have it confirmed by someone with licence expertise.
